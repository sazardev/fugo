Versionamiento

La versión de Fugo sigue intencionalmente a Flutter: VERSION es <versión-de-flutter>-fugo.<build> (por ejemplo 3.44.8-fugo.0) — los primeros tres números siempre son la versión exacta del SDK de Flutter contra la que están compilados el cliente precompilado y flutter_client/, así que nunca hay ambigüedad entre un release de Fugo y el Flutter con el que renderiza.

FLUTTER_VERSION es la única fuente de verdad para ese pin: release-flutter-client.yml compila exactamente contra esa versión (no un canal flotante como stable), y fugo doctor avisa (no falla — el SDK de Flutter es opcional) si tu Flutter instalado no coincide.

Un workflow semanal, check-flutter-version.yml, revisa si hay una versión estable de Flutter más reciente y abre un PR para actualizar el pin — Fugo está pensado para seguir a Flutter de forma continua, no quedarse atrás. Ese PR nunca se mergea automáticamente, porque una actualización de Flutter puede romper el código Dart de flutter_client/.

Dos comandos cubren un release, ninguno edita VERSION/CHANGELOG.md a mano: make release MSG="..." sube solo el sufijo -fugo.N (un fix de Fugo contra la misma versión de Flutter); make release-flutter FLUTTER=<version> MSG="..." sube la versión de Flutter objetivo (reinicia a -fugo.0). Ya no existe TYPE=patch|minor|major — mayor/menor no significan nada bajo este esquema.

3.44.8-fugo.02026-08-02

Cambiado

  • La versión de Fugo ahora sigue exactamente la versión del SDK de Flutter que usa. VERSION es <versión-de-flutter>-fugo.<build> (ej. 3.44.8-fugo.0) — los primeros tres números siempre indican exactamente contra qué versión de Flutter están compilados el cliente precompilado y flutter_client/, así que nunca hay ambigüedad entre un release de Fugo y el Flutter con el que renderiza. FLUTTER_VERSION es la nueva fuente única de verdad para ese pin: CI (release-flutter-client.yml) compila exactamente contra esa versión en vez de un canal flotante channel: stable, y fugo doctor avisa si tu SDK de Flutter instalado no coincide.

Subir la versión de Flutter objetivo es un paso separado y explícito: make release-flutter FLUTTER=<version> MSG="...".
  • Un nuevo workflow programado (check-flutter-version.yml) revisa semanalmente si hay una versión estable de Flutter más nueva y abre un PR que sube FLUTTER_VERSION — Fugo está pensado para seguir a Flutter actual, no quedarse atrás. Ese PR siempre necesita revisión y merge humano (una actualización de Flutter puede afectar el código Dart de flutter_client/), nunca se auto-mergea.
0.17.02026-06-09

Añadido

  • fugo doctor ahora verifica coherencia del proyecto: lee la ruta del módulo de go.mod y el import <module>/ui de main.go, y reporta un ✗ preciso cuando no coinciden, cuando falta el paquete ui importado, o cuando no tiene un Build exportado — detectado antes del error de compilación genérico.
  • fugo doctor --fix repara las partes auto-corregibles dentro de un proyecto antes de diagnosticar: escribe un fugo.toml por defecto si falta, corre git init si no hay repo, y go mod tidy para resolver dependencias.

Cambiado

  • fugo run hace hot-reload por defecto. Ahora vigila los archivos .go y reconstruye/reconecta el servidor Go en cada cambio mientras la ventana de Flutter permanece abierta — así que los cambios en texto, handlers, layout, etc. se ven en vivo (el estado en memoria se reinicia entre recargas). Pasa --no-watch para un solo build-and-run; el antiguo flag --watch ahora está implícito (oculto, no-op).

Corregido

  • Cliente de render Flutter: la reconexión tras un reinicio del servidor (hot reload) ya no falla con "Bad state: Stream has already been listened to". El isolate ahora se suscribe a su ReceivePort una sola vez y enruta eventos al stream activo, y reinicia su backoff tras una sesión exitosa para reconectar en ~500ms.
0.16.02026-06-09

Añadido

  • fugo doctor ahora es un chequeo de salud en dos partes. Toolchain: Go, Flutter, git, protoc, gofumpt (Go/Flutter son requeridos → ✗; el resto son advertencias) más la plataforma. Proyecto (al correr dentro de un proyecto Fugo): importa fugo.toml y reporta la ventana/dirección resuelta, verifica que la dirección gRPC configurada esté libre (o sea un unix socket), verifica la estructura (main.go, ui/, go.mod), que el módulo github.com/sazardev/fugo resuelva, si el cliente Flutter está compilado (o es compilable), y finalmente compila el proyecto (go build ./...).

Cambiado

  • fugo doctor ahora sale con código distinto de cero cuando hay un problema bloqueante (falta una herramienta requerida, un módulo sin resolver, o un proyecto que no compila), para poder usarlo como gate en scripts/CI. Las advertencias por sí solas mantienen un código de salida cero.
0.15.02026-06-09

Añadido

  • fugo init ahora genera una estructura de proyecto recomendada en vez de un main.go solitario: un entrypoint main.go delgado, un paquete ui para tus pantallas (ui.Build), una config fugo.toml, un README.md, un .gitignore, y logs/ (con bin//dist/ reservados para la salida del build). También corre git init y hace un commit inicial (omítelo con --no-git).
  • fugo.toml — configuración declarativa de proyecto leída por el CLI y la app: [window] title/width/height y [server] addr. El main.go generado lo carga vía el nuevo fugo.ConfigOptions("fugo.toml"); fugo run usa [server] addr como dirección por defecto (aún se puede sobreescribir con --addr), y fugo build incluye fugo.toml en dist/.
  • Nuevo paquete config libre de dependencias (github.com/sazardev/fugo/config) que carga fugo.toml (un subconjunto pequeño y fijo de TOML), compartido entre el runtime y el CLI.
  • fugo run ahora copia los logs de runtime de la app a logs/run.log (además de seguir mostrándolos en la consola).

Cambiado

  • Las plantillas iniciales app y showcase ahora viven en el paquete ui generado (ui.Build); el tema se configura en main.go antes de RunStandalone.

0.3.02026-06-09

Añadido

  • Instalable vía go install: los bindings de protobuf de Go generados están commiteados, así que un fetch limpio compila el CLI sin protoc.
  • Servicios nativos del SO: portapapeles (Context.Clipboard()) y diálogos de archivo nativos (Context.Files().Open/Save).
  • Control de ventana en tiempo de ejecución vía Context.Window().
  • Nuevos widgets: fg.AnimatedPositioned y fg.WindowDragArea.
  • Ruta de prioridad inmediata del scheduler: Context.UpdateNow().

Cambiado

  • Los bindings de protobuf de Go generados ya no están en gitignore — commiteados y mantenidos limpios con gofumpt.
  • Rendimiento: mapa de búsqueda de diff con pool de objetos, ajuste de GC, benchmarks Go + Dart detrás de un gate de regresión de rendimiento en CI.
0.2.02026-06-08

Añadido

  • Renovación de DX del CLI: logging verbose/quiet nivelado, pasos animados, ayuda enriquecida, un catálogo de widgets, FUGO_LOG.

Corregido

  • Data race en App.handlers entre el scheduler y las goroutines de transporte (ahora protegido con mutex).
  • Desincronización de diff con keys — la identidad del nodo ahora es posicional por id, así que cada patch es aplicable en el cliente.
  • Propiedades de Text y Container que se podían configurar pero nunca llegaban al cable.

Cambiado

  • Se re-establecieron los presupuestos de rendimiento sobre protobuf estándar con un gate de diff determinista de cero-allocs.
